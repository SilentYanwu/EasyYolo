# EasyYolo 数据库结构

> 数据库引擎：SQLite | ORM：SQLAlchemy | 文件位置：`database/yolo_app.db`

## 1. 概述

数据库共 **2 张表**：`inference_history`（推理历史记录）和 `training_history`（训练历史记录）。表在应用首次启动时由 SQLAlchemy 自动创建（`Base.metadata.create_all`），无需手动建表。

每个模型在 `inference_history` 中最多保留 **199 条**记录（由 `MAX_RECORDS_PER_MODEL` 控制），超出时自动删除最旧的记录及其关联的物理文件。

---

## 2. 推理历史表 — `inference_history`

存储每次推理任务的输入输出记录，按模型名分类查询。

### 2.1 字段定义

| 字段名 | SQL 类型 | 约束 | 说明 |
|:-------|:---------|:-----|:-----|
| `id` | `INTEGER` | **PRIMARY KEY**, AUTOINCREMENT, INDEX | 自增主键，唯一标识每条推理记录 |
| `model_name` | `TEXT` | **NOT NULL**, INDEX | 推理时使用的模型文件名（如 `yolo11n.pt`），用于按模型筛选历史 |
| `original_url` | `TEXT` | 可空 | 原始上传图片的存放路径（相对于 `inferecord/uploads/`） |
| `result_url` | `TEXT` | 可空 | 推理结果图片的存放路径（相对于 `inferecord/results/`），图片上带有 YOLO 绘制的检测框 |
| `created_at` | `DATETIME` | 默认 `datetime.now` | 推理记录的创建时间 |

### 2.2 索引

| 索引名 | 字段 | 用途 |
|:-------|:-----|:-----|
| 主键索引 | `id` | 按 ID 排序/查询 |
| 普通索引 | `model_name` | 按模型名筛选历史记录 |

### 2.3 清理机制

当某个 `model_name` 的记录数超过 `MAX_RECORDS_PER_MODEL`（199 条）时，自动删除 ID 最小的旧记录，同时删除对应的 `uploads/` 和 `results/` 物理文件。清理在每次 `add_record()` 插入新记录后触发。

### 2.4 涉及的操作

| 操作 | 说明 |
|:-----|:-----|
| `add_record()` | 新增一条推理记录，触发旧记录清理 |
| `get_history(model_name)` | 按模型名查询所有历史记录（倒序） |
| `delete_record(record_id)` | 删除单条记录 + 对应的上传/结果文件 |
| `clear_history(model_name)` | 清空某模型的所有记录 + 对应文件 |
| `update_model_name(old, new)` | 批量更新某模型名（重命名模型时级联更新） |

---

## 3. 训练历史表 — `training_history`

存储每次训练任务的详细参数、指标和产物信息。`model_name` 是该表的核心关联字段（既是主键，也是与 `models/trained/` 目录下的 `.pt` 文件的对应键）。

### 3.1 字段定义

| 字段名 | SQL 类型 | 约束 | 说明 |
|:-------|:---------|:-----|:-----|
| `id` | `INTEGER` | **PRIMARY KEY**, AUTOINCREMENT, INDEX | 自增主键 |
| `model_name` | `TEXT` | **UNIQUE**, **NOT NULL**, INDEX | 训练产出的模型文件名（如 `steel_v1.pt`），是这张表的业务主键，与 `models/trained/` 下的 `.pt` 文件一一对应 |
| `base_model` | `TEXT` | 可空 | 训练时使用的基础模型名（如 `yolo11n.pt` 或前一个训练产出的模型名） |
| `dataset` | `TEXT` | 可空 | 训练使用的数据集名称（对应 `datasets/` 下的目录名） |
| `parameters` | `TEXT` | 可空 | 训练超参数 JSON 字符串，见 [3.2 节](#32-parameters-字段结构) |
| `description` | `TEXT` | 默认 `""` | 用户自定义的模型介绍文本 |
| `best_metrics` | `TEXT` | 默认 `""` | 训练过程中最佳一轮的指标 JSON 字符串，通常包含 mAP50、mAP50-95、precision、recall 等 |
| `best_epoch` | `INTEGER` | 默认 `0` | 最佳指标出现在第几个 epoch。`0` 表示未记录 |
| `early_stopped` | `INTEGER` | 默认 `0` | 训练是否因早停而提前结束：`0` = 正常完成全部 epochs，`1` = 触发早停自动结束 |
| `early_stop_epoch` | `INTEGER` | 默认 `0` | 早停发生时的 epoch 数。`0` 表示未发生早停 |
| `eval_table` | `TEXT` | 默认 `""` | 每类（per-class）评估指标表 JSON 字符串，包含每个类别的 AP、precision、recall 等 |
| `created_at` | `DATETIME` | 默认 `datetime.now` | 训练完成时间（即本条记录入库时间） |

### 3.2 `parameters` 字段结构

JSON 字符串，内容为 Ultralytics YOLO 训练超参数。典型字段：

```json
{
  "epochs": 60,
  "patience": 15,
  "batch": 12,
  "imgsz": 640,
  "optimizer": "auto",
  "lr0": 0.01,
  "lrf": 0.01,
  "momentum": 0.937,
  "weight_decay": 0.0005,
  "warmup_epochs": 3.0,
  "warmup_momentum": 0.8,
  "cos_lr": false
}
```

### 3.3 `best_metrics` 字段结构

JSON 字符串，记录训练中验证集表现最好那一轮的指标。典型字段：

```json
{
  "metrics/precision(B)": 0.9234,
  "metrics/recall(B)": 0.8812,
  "metrics/mAP50(B)": 0.9156,
  "metrics/mAP50-95(B)": 0.7234
}
```

### 3.4 `eval_table` 字段结构

JSON 字符串，为每个类别独立评估的指标列表。每条记录包含：

```json
[
  {
    "Class": "defect_a",
    "Images": 200,
    "Instances": 350,
    "Precision": 0.912,
    "Recall": 0.875,
    "mAP50": 0.903,
    "mAP50-95": 0.698
  },
  {
    "Class": "defect_b",
    "Images": 200,
    "Instances": 120,
    "Precision": 0.834,
    "Recall": 0.792,
    "mAP50": 0.821,
    "mAP50-95": 0.567
  }
]
```

### 3.5 `early_stopped` 与 `early_stop_epoch` 的含义

| early_stopped | early_stop_epoch | 含义 |
|:--------------|:-----------------|:-----|
| `0` | `0` | 训练正常跑完所有 epochs，未触发早停 |
| `0` | `> 0` | 不会出现此组合 |
| `1` | `> 0` | 训练在第 N 轮触发早停，N 轮时指标不再提升，提前结束 |
| `1` | `0` | 不会出现此组合 |

### 3.6 索引

| 索引名 | 字段 | 用途 |
|:-------|:-----|:-----|
| 主键索引 | `id` | 自增排序 |
| UNIQUE 索引 | `model_name` | 确保模型名唯一，作为业务主键 |

### 3.7 涉及的操作

| 操作 | 说明 |
|:-----|:-----|
| `add_training_record()` | 新增或覆盖训练记录（同名模型再次训练时更新全部字段，`created_at` 刷新为当前时间） |
| `get_training_record(model_name)` | 获取单个模型的完整训练详情 |
| `delete_training_record(model_name)` | 删除某模型的训练记录 |
| `update_training_record_name(old, new)` | 同时更新两个维度：① 该模型自身的 `model_name`；② 其他模型中将其作为 `base_model` 的字段值 |
| `update_training_record_description(model_name, description)` | 仅更新模型介绍（不刷新 `created_at`） |

---

## 4. 表间关系

两张表通过 **`model_name` 字段** 隐式关联：

```
training_history.model_name ──────────────────────────── inference_history.model_name
       (训练产出模型)                                          (推理使用模型)
              │                                                        │
              │  1. 推理时用户选择一个模型 → inference_history.model_name               │
              │  2. 重命名模型时两表同时更新 model_name                                │
              │  3. 删除模型时两表相关记录级联删除 + 物理文件清理                           │
              │                                                        │
              └─── models/trained/{model_name}.pt (物理文件) ──────────┘
```

**注意**：`training_history` 中 `base_model` 字段也可能指向另一个 `model_name`（队列训练中任务 N 使用任务 N-1 产出模型作为基础模型）。重命名时 `update_training_record_name()` 同时更新 `model_name` 和 `base_model` 两处引用。

---

## 5. 自动迁移

数据库文件在 `Base.metadata.create_all()` 时自动创建。对于后续新增的字段（`best_metrics`、`best_epoch`、`eval_table`），代码中通过 `ALTER TABLE ... ADD COLUMN` 做兼容迁移。这些语句包裹在 try-except 中，因为如果字段已存在则 SQLite 会报错，此时静默跳过。

迁移字段历史：

| 字段 | 添加原因 |
|:-----|:---------|
| `best_metrics` | 记录训练过程中最佳一轮的指标，用于详情页展示 |
| `best_epoch` | 记录最佳指标出现在哪一轮 |
| `eval_table` | 记录每类独立评估指标，用于详情页渲染分类指标表 |
